# Epic 5 Context: 转人工升级与 AI 身份合规

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

实现硬触发条件的转人工全流程与 AI 身份合规保障。红线意图（价格谈判、贷款政策、投诉）、非文本输入、同一意图追问达阈值、负面词汇这四类硬触发必须 100% 将会话即时转交经纪人工作台，全程零 AI 生成回答，且买家在等待期间收到明确的安抚通知。同时保证 Agent 响应始终携带 AI 身份标识、转人工后标识干净切换为经纪人身份，避免人机混答与合规风险。该 Epic 是全系统的合规红线出口，判定口径必须可审计、可灰度调整。

## Stories

- Story 5.1: 硬触发条件判定
- Story 5.2: Kafka 转人工单向指令
- Story 5.3: 转人工原子终态与买家安抚通知
- Story 5.4: AI 身份披露标识

## Requirements & Constraints

- 硬触发条件集为：红线意图（NEGOTIATION / LOAN_POLICY / COMPLAINT）、图片/语音输入、同一意图追问 ≥3 次、负面词汇命中。命中任一即立即触发转人工，红线意图必须 100% 转人工、零生成回答。
- 硬触发条件集（追问阈值、负面词表、意图范围）必须配置化，默认按产品需求取值，支持灰度调整以避免追问误触发造成噪音转接。
- 从触发转人工到消息送达经纪人工作台的延迟 P99 < 5s。
- 买家安抚通知文案固定为"已为您转接经纪人，请稍候"，由本服务下发。
- 转交指令 payload 须携带会话上下文（含最近 3 轮对话摘要），经纪人接管时无需翻阅历史。
- 指令发送失败重试 3 次后写死信队列并触发人工告警，禁止静默降级为模板应答。
- Agent 响应 100% 携带"AI 助手"标识；转人工后标识消失，切换为经纪人姓名/头像，无残留；AI 标识的展示与切换可通过 Langfuse trace 对应的会话记录验证。
- 判定与触发过程须记录可观测数据（命中条件、触发结果均写 trace），便于审计漏判。

## Technical Decisions

- 硬触发评估集中归属：全部四类硬触发条件由 intent_router 过滤器内单一硬触发评估模块统一判定，判定结果（触发/未触发 + 命中条件）写入信封并记录 Langfuse trace；禁止四类条件分散在多个过滤器各自评估。
- 追问计数以 Redis 权威值为准，不读 L1 进程内快照；负面词汇词库由风控中台提供，服务内只读加载。
- 图片/语音输入由接入适配器在信封标注媒体类型，硬触发评估模块对非文本输入直接判触发；意图分类与 LLM 链路不处理非文本输入。
- 硬触发命中即路由至转人工分支，禁止任何过滤器在命中后继续走缓存/LLM 路径。
- 转人工 = Kafka 转交指令（发往 SpringBoot 经纪人工作台）+ 买家安抚通知（发往下发适配器），两个动作由转人工分支顺序执行，严格先指令后通知。
- 转人工分支为原子终态出口：禁止回流响应组装/下发路径，禁止在该分支使用模板兜底文案；转人工后该 session 的 Agent 响应路径关闭。转人工分支是全系统错误处理约定的唯一例外，不降级模板兜底。
- 会话状态为单写者模型：handoff 状态作为会话状态子字段，由转人工分支经会话管理模块写入；经纪人工作台侧展示状态以 Kafka 指令为准。
- 信封为单一 Pydantic 模型，转人工相关判定结果经信封字段传递；意图标签为单一 Literal 枚举，全链路 model_validate 校验。
- AI 身份披露由响应组装过滤器承载（Agent 响应 100% 携带标识）；Agent 生成文本不得包含"我是这套房的经纪人"或等价表述，该约束纳入风控审核范围。

## UX & Interaction Patterns

- AI 身份标识经经纪人工作台聊天界面承载，本服务不新增 UI 工作；服务侧负责保证 Agent 响应携标、转人工后切换为经纪人姓名/头像且无残留。
- 转人工后买家进入真人服务等待态，期间不得再收到任何 AI 回复，避免人机混答。

## Cross-Story Dependencies

- 依赖 Epic 1 提供的管道基座、信封/会话状态/Kafka 适配基础设施，以及 handoff 状态的会话管理写入能力。
- 依赖 Epic 2 的意图分类标签与追问计数（Redis 权威值），硬触发判定消费其输出。
- 依赖 Epic 4 的响应组装与下发链路，AI 身份标识（Story 5.4）在响应组装环节注入。
